### Query log types

| Type | Lines | What it simulates | How the queries look |
|---|---|---|---|
| *_1 Popularity* | 100 | 8 queries asked 12× each, 4 asked once | one path with an *exact node ID*, e.g. 8324.born."1953" |
| *_2 Shifting interest* | 200 | 5 batches, each with a new dominant query (26×), a second one (10×) and an older one returning (4×) | one path with an *exact node ID*, e.g. 43.name."Cillian Murphy" |
| *_3 Complex* | 20 | different combined questions | *variables*, built from one real movie: movie facts only (X1.genre."Drama",X1.genre."Sci-Fi") or a person who appears in 2+ movies plus movie facts (X1.name."Ed Skrein",X1.actedIn.X2,X2.genre."Sci-Fi") |
| *_4 Sub-queries* | 50 | queries contained in bigger queries | *variables*: 5 big queries (up to 2 people + movie facts, 4 conditions), each followed by 9 smaller queries made of 2–3 of its conditions |

We have *8 databases × 4 query log types = 32 query logs*, generated by src/generate_qlogs.py (seed 1).
File names: QLog{group number}_{db}_{type}.txt, where db 1–8 is Database24_1–Database24_8.


### How many graphs answer a query

- *_1 and _2*: almost always 1 answer, because the queries name an exact node.
- *_3*: on the 1,000-graph databases, about 12 of 20 queries have several answers.
- *_4*: about 18 of 50 queries have several answers.
- *20-graph databases (Database24_1–_4)*: mostly 1 answer for every type.

The number of answers per query decides whether reduction methods can differ: when a query has only one answering graph, every reasonable method keeps the same graph.
